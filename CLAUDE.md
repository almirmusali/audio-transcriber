# Транскрибер — память проекта

Нативное Mac-приложение: Electron + whisper.cpp на Metal, модель `large-v3-turbo`,
плюс веб-версия (`server/server.mjs`) для доступа со студии.

## Личный словарь whisper

`electron/whisper-dict.cjs` и `server/whisper-dict.mjs` — **две копии одного модуля**
(CommonJS для Electron, ESM для сервера). Правишь один — правь и второй, иначе
приложение и веб начнут распознавать по-разному.

Словарь собирается из `~/.config/whisper/dictionary.txt` (общий для всех проектов)
и `whisper-dictionary.txt` в корне проекта, и уезжает в whisper через `--prompt`
и `--carry-initial-prompt`.

**Главная грабля: whisper режет подсказку с начала.** Лимит — `n_text_ctx/2` ≈ 224
токена, и при переполнении остаётся **хвост**, а голова выбрасывается. То есть самые
важные термины, поставленные первыми, пропадают первыми, и молча: словарь выглядит
рабочим, а половина имён по-прежнему коверкается.

Поэтому режем сами, по бюджету в 200 токенов (`WHISPER_DICT_TOKENS`), с оценкой
`estimateTokens` — кириллица дробится примерно вдвое мельче латиницы. Коэффициенты
не выдуманы, а сняты замером: кириллическая подсказка начинает терять голову около
410 символов. При переполнении `warnDictionaryOverflow` пишет в лог, что не влезло.

В словарь идут только слова, которые распознавалка реально портит. Обычные русские
слова отъедают бюджет у настоящих имён.

## Как проверять распознавание

Не юнит-тестом: сквозным прогоном на живой речи. Синтезируем фразу системным голосом
и гоняем через тот же бинарник, что и приложение:

```bash
say -v Milena -o t.aiff "фраза с проверяемыми именами"
resources/bin/ffmpeg -y -i t.aiff -ar 16000 -ac 1 -c:a pcm_s16le t.wav
P=$(node -e "console.log(require('./electron/whisper-dict.cjs').whisperPrompt(process.cwd()))")
resources/bin/whisper-cli -m resources/models/ggml-large-v3-turbo-q5_0.bin \
  -f t.wav -l ru -nt --prompt "$P" --carry-initial-prompt
```

Прогон без `--prompt` — это база для сравнения. Считается доказанным только то,
что видно в разнице двух прогонов.
